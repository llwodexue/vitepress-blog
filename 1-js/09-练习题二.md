# 练习题二

## 一、请说出最终的执行结果

```js
var a = []
for (var i = 0; i < 10; i++) {
  a[i] = function () {
    console.log(i)
  }
}
a[6]()
```

结果是 10

## 二、请说出最终的执行结果

```js
var tmp = 123
if (true) {
  console.log(tmp)
  let tmp
}
```

报错。`let` 的声明同样会在其块级作用域中建立绑定，但在声明语句执行前处于暂时性死区（TDZ），因此不能访问。

## 四、var、let、const 区别

|            | var                             | let                | const                                      |
| ---------- | ------------------------------- | ------------------ | ------------------------------------------ |
| 提升       | 声明提升，使用 undefined 初始化 | 建立绑定，但声明前处于 TDZ | 建立绑定，但声明前处于 TDZ                 |
| 作用域     | 全局                            | 块级               | 块级                                       |
| 初始化     | 可以仅声明不初始化              | 可以仅声明不初始化 | 必须在声明时初始化                         |
| 重复定义   | 可以                            | 不可以             | 不可以                                     |
| 多次赋值   | 可以                            | 可以               | 绑定不可重新赋值；对象本身仍可能可变       |
| 声明前访问 | 可以                            | 不可以             | 不可以                                     |

## 五、请说出最终的执行结果

```js
var a = 10
var obj = {
  a: 20,
  fn() {
    setTimeout(() => {
      console.log(this.a)
    })
  },
}
obj.fn()
```

结果是 20。`setTimeout` 中的回调是箭头函数，里面的 this 指向没有改变，和 fn 函数里的 this 一致，都指向 obj

## 六、简述 Symbol 类型的用途

- 作为对象的属性，可以作为对象的私有属性
- 阻止对象上属性名的冲突，每个 Symbol 都是独一无二的，可以保证不与其他属性名产生冲突
- 使用 Symbol 来代替常量

## 七、什么是浅拷贝，什么是深拷贝

浅拷贝：针对 Object、Array 这种复杂数据类型，浅拷贝复制一层对象的属性，属性中的值是基本数据类型，直接复制值；如果是引用类型，复制内存地址指针，所以在修改复制后的变量里引用类型的里面的值时，会导致原始数据也被修改

深拷贝：针对 Object、Array 这种复杂数据类型，递归复制了所有的层级，新数据和原始数据不存在联系，因此在修改复制后的变量里引用类型的里面的值时，不会导致原始数据也被修改

## 八、简述 TS 和 JS 之间的关系

TypeScript 是 JavaScript 的语法超集；类型会在编译后擦除。它提升静态检查和编辑体验，但 API 返回值、外部数据和权限等运行时边界仍需校验。

| TypeScript | JavaScript |
| --- | --- |
| 在 JavaScript 上增加静态类型、接口和类型工具 | 语言本身不提供 TypeScript 的类型检查 |
| 编译期可发现部分不一致 | 运行时按实际值执行 |
| 可编译为目标环境支持的 JavaScript | 原生支持的语法取决于运行时 |
| 类型参数和接口仅存在于编译期 | 支持 ES Modules；泛型是 TypeScript 的类型系统能力 |

## 九、请谈谈你认为的 TS 优缺点

优点：

- 可编译为目标运行环境支持的 JavaScript
- 功能更为强大，生态更健全、更完善
- TypeScript 属于渐进式的
- 增强代码的可读性和可维护性，增强了编译器和 IDE 的功能，定义可以作为文档
- 在编译阶段发现一部分类型不一致，不能替代运行时校验

缺点：

  - 语言本身多了很多概念，提高学习成本
  - 项目初期，TypeScript 增加开发成本
  - 集成到构建流程需要一些工作量
  - 可能和一些库结合不完美，需要单独添加一些声明，不过大部分的库都支持了 TypeScript

## 十、描述引用计数的工作原理和优缺点

工作原理：设置引用数，判断当前引用数是否为 0，引用关系改变时修改引用计数

优点：

1. 发现垃圾时立即回收
2. 最大限度减少程序暂停（保证空间不会占满）

缺点：

1. 无法回收循环引用对象
2. 时间开销大（监控对象，维护引用数）

## 十一、描述标记整理算法的工作流程

1. 遍历所有对象并标记活动对象

2. 清除阶段会先执行整理，移动对象位置，将活动对象放在一起

3. 清除没有标记的对象，同时把第一次遍历所做的标记抹掉

4. 把回收的空间放到空闲列表上面，方便后续程序申请空间使用

优点：

- 减少了内存空间的碎片化

缺点：

- 不能立即回收对象

## 十二、描述 V8 中新生代存储区垃圾回收的流程

V8 会将新生代划分为两个半空间，并以复制为主处理存活对象；存活对象可能因年龄或空间压力晋升到老生代。半空间大小、晋升条件和具体算法随 V8 版本、平台和运行参数变化，不能将固定数值或单一阈值作为通用结论。诊断应以目标环境的堆快照和 GC 性能录制为准。

## 十三、描述增量标记算法在何时使用及工作原理

使用时机：

- 会穿插在程序的运行中执行

工作原理：将可达性标记拆分为可中断的小步，与 JavaScript 执行交替进行以降低长暂停。并发标记、写屏障和整理策略是引擎实现细节，具体行为应以当前 V8 文档和性能数据为准。
