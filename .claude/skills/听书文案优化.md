# 听书文案优化

适用于 `8-notes` 目录下以书籍解读、听书转述为主的 Markdown 文稿。

## 目标

- 保留“得到”式的口语讲述感和知识交付感，但不保留平台话术
- 让读者能清楚回答：这本书的核心观点是什么、为何成立、可以如何理解或行动
- 精炼冗余，不把有价值的论证压缩成只有结论的书摘
- 删除重复不等于缩短篇幅：核心章节必须保留支撑观点的场景、推演与结果，不能优化成只有框架和行动清单的提纲
- 区分作者主张、可核验事实与编辑补充；对教育、健康等高泛化建议保留边界
- 合理使用 Markdown 与 VitePress 语法，让长文可扫读、可朗读、可复盘

## 先做结构扫描

优化前先识别：开场定位、核心问题、章节观点、典型场景、论证链、行动结尾。不要按原稿段落机械删改；先确定全书的主线和每章不可缺失的信息。

每个核心章节至少保留：

- 一个能体现作者立场的典型问题或场景
- 一条完整的“观点 → 原因 → 结果”逻辑链
- 一句必要的转场或小结，保持朗读时的节奏

当原稿存在整段重复时，优先删除重复副本，再重写重复表达；不要为了追求篇幅把剩余正文继续压缩。优化后的篇幅应由论证密度决定，而不是以“越短越好”为目标。

## 推荐结构

```text
标题：书名 + 一句最独特的核心结论
开场破题：金句 + 反常识观点或极端困境 + 本书承诺（30 秒内）
关键问题：3～5 个，先给结论再解释
核心框架：按主题展开“场景/问题 → 观点 → 推演 → 边界”
行动结尾：以自然的动作型标题给出一个最小、具体的行动，或留下一个可延伸的问题
```

不强制所有文稿使用全部层级；以书的内容和原稿质量为准。概念型书籍可突出框架，故事型书籍应保留推动结论的关键故事。

## 开头破题：30 秒抓住注意力

开头不从“欢迎收听”、作者履历、解读背景或全书目录开始。用约 80～150 字完成三件事：

1. **金句前置**：第一句说清这本书解决的根本问题
2. **冲突切入**：抛出一个反常识观点，或一个读者熟悉的极端困境
3. **阅读承诺**：说明下文会解释什么新的视角、判断或方法

模板：

> **这本书解决的根本问题是：___。** 如果 ___，为什么反而会 ___？作者给出的反常识答案是 ___。接下来，我们就看这套判断如何成立。

开头只负责让读者进入问题，详细论证留给正文。避免在 30 秒内塞入过多结论或背景信息。

## 删改规则

### 直接删除

- 平台欢迎语、主播与解读人介绍、作者无关履历
- 音频、文稿、分享、购买或阅读原书等导流话术
- 与本书论点无关的个人经历
- 同一观点的重复反问、感叹和多轮举例

### 必须保留或压缩保留

- 核心论点及其因果链
- 有助理解作者立场的一个典型场景
- 章节间必要转场和段末小结
- 争议性观点的来源、适用范围或不能推导出的结论

### 保留案例，但压缩案例

案例不是装饰，而是让抽象观点可被代入的证据。每条核心主线优先保留一个短案例；案例较多时，保留最能展示“说法或行动改变后，关系/结果如何变化”的一个。

推荐结构：

```text
案例标题：一句话说明场景中的转变
孩子/当事人：发生了什么
容易出现的回应：原本会怎么说、怎么做
更有帮助的回应：改成什么说法、什么动作
一句解释：为什么这一改变有效，边界在哪里
```

案例应压缩为一个小场景，不逐句转录长对话；保留推动结论的关键两到四句即可。可使用引用块或“反例 / 改说法”表格呈现，避免多个同质案例连续堆叠。

### 处理“车轱辘话”

同一信息只保留一次完整表达。后续重复内容优先：

1. 删除没有新增信息的句子
2. 将不同表述合并成一条更短的因果链
3. 需要承接时，用逻辑连接词推进，不另起一轮解释

优先使用“换句话说”“本质上”“这意味着”“因此”“但边界是”串联逻辑；少用连续反问、感叹和“你有没有发现”式引导。

示例：

> 原意：父母持续进步，孩子会跟着进步；你做到了，比说一万句都有用。
>
> 改写：父母持续成长，比反复说教更有示范力。换句话说，孩子模仿的不是要求，而是每天看见的生活方式。

## 表达边界

- 作者观点使用“书中认为”“作者主张”“这一视角指出”，不要无依据地改写为普遍事实
- 避免“必然”“唯一”“注定”等绝对化结论；证据不足时改为“可能”“通常”“值得警惕”
- 健康、心理、教育建议应说明个体差异；不把单一训练、饮食或教养方式写成通用处方
- 保留自然口语，但一段只服务于一个观点，避免口语填充词堆叠

## Markdown 格式

格式必须服务信息，不为装饰堆叠语法。优先按信息关系选择：

| 信息类型 | 推荐格式 |
| --- | --- |
| 全文最重要的视角 | `::: tip` 摘要容器 |
| 多个并列概念或对照关系 | Markdown 表格 |
| 一句话原则、关键转折 | 引用块 `>` |
| 必须限定的适用范围 | `::: info`；存在风险时用 `::: warning` |
| 可执行的收尾动作 | `::: tip` 行动卡片 |
| 有先后顺序的流程 | 有序列表 |

使用规则：

- 标题层级从 `#` 开始顺序递进，不跳级
- 使用 **粗体** 标示一句中的关键结论，不整段加粗
- 表格只用于横向对照；单列信息使用列表或段落
- 不使用 `::: details` 折叠内容；听书稿的补充说明应直接展开
- `::: info` 用于补充解释与适用边界，`::: warning` 用于风险提醒，`::: tip` 用于核心结论或行动建议
- 提示容器仅用于真正需要强调或提醒的内容，每个章节不宜堆叠多个
- 代码格式仅用于术语、命令、变量或需要保持字面形式的外文词；不要把普通中文概念写成代码

## 结尾：行动，而非全书复述

结尾不再总结全书框架，也不使用“以上就是本书解读”等收束语。根据文稿选择其一：

行动建议与思考钩子通常二选一，避免结尾同时承担两个重点。

### 给出一个最小行动

给出一个与全书核心方法一致、低门槛且可在本周开始的动作。动作必须具体，避免“多陪伴”“持续成长”这类空泛要求。

示例：

> 如果只做一件事，就在本周选一次亲子冲突，先不急着纠正孩子，先问自己：我希望他从这件事里学会承担什么后果？

### 留下一个钩子

提出一个没有被本书完全解决、但能引向更深问题的提问。钩子应来自本书的主线，不能是泛泛的鸡汤式设问。

示例：

> 当父母和孩子对“什么样的人生更好”有不同答案时，家庭规则究竟该保护谁的选择？

## 发布前检查

- 开头能否在 30 秒内说明“这本书讲什么、为何值得听”
- 每个核心章节是否包含观点、理由和必要边界
- 是否删掉平台信息、人物介绍、导流和无关自述
- 是否删掉车轱辘话，而非删掉支撑主论点的推演
- 每条核心主线是否保留了一个能说明转变的短案例
- 连接词是否真正推进逻辑，而非把重复内容换一种说法
- 结尾是否只留下一个行动或一个钩子，而不是总结全书
