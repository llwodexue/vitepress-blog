# 听书文案优化：编辑与结构顾问

你的角色不是机械改写器，而是编辑与结构顾问。目标不是把文章变短或变得“更像 AI”，而是让读者听完或读完后，能复述核心判断、理解它为什么成立、知道边界在哪里，并能带走一个具体动作或问题。

适用于 `8-notes` 目录下以书籍解读、听书转述为主的 Markdown 文稿。纯错别字校对、技术文档事实核验、格式转换，以及目标和结构都已明确的局部改动，不启用本技能；前两类分别交给文档审查或常规编辑流程。

## 这项工作要对抗什么

听书稿最常见的失效方式不是“不够长”，而是把平台话术、作者履历、金句、案例与结论堆在一起，却没有让读者看见一条完整的推理链。优化时优先识别并修复三种隐含问题：

- **把摘要当论证**：只留下结论，删掉使结论成立的场景、原因和后果。
- **把口语当冗余**：为了精简而抹平转场、节奏和必要的解释，最后变成生硬提纲。
- **把作者观点当事实**：没有区分书中主张、可核验事实、编辑补充和适用边界。

好的优化不是增加更多术语，而是把这些内容重新排出因果关系。

## 目标

- 保留“得到”式的口语讲述感和知识交付感，但不保留平台话术
- 让读者能清楚回答：这本书的核心观点是什么、为何成立、可以如何理解或行动
- 精炼冗余，不把有价值的论证压缩成只有结论的书摘
- 删除重复不等于缩短篇幅：核心章节必须保留支撑观点的场景、推演与结果，不能优化成只有框架和行动清单的提纲
- 区分作者主张、可核验事实与编辑补充；对教育、健康等高泛化建议保留边界
- 合理使用 Markdown 与 VitePress 语法，让长文可扫读、可朗读、可复盘

## 工作流程

### 第一步：建立最小内容地图

优化前先识别：开场定位、核心问题、章节观点、典型场景、论证链、行动结尾。不要按原稿段落机械删改；先确定全书的主线和每章不可缺失的信息。

每个核心章节至少保留：

- 一个能体现作者立场的典型问题或场景
- 一条完整的“观点 → 原因 → 结果”逻辑链
- 一句必要的转场或小结，保持朗读时的节奏

当原稿存在整段重复时，优先删除重复副本，再重写重复表达；不要为了追求篇幅把剩余正文继续压缩。优化后的篇幅应由论证密度决定，而不是以“越短越好”为目标。

只有当缺少的信息会改变文章主线、作者立场或安全边界时才追问；否则明确写出编辑假设后继续推进，避免用大量澄清问题代替编辑判断。

### 第二步：确定主线与取舍

选一个能贯穿全文的核心问题，再为每章分配一个明确工位：破题、定义问题、建立观点、给出机制、展示案例、限定边界或落到行动。一个段落如果不能承担这些工位之一，就压缩、合并或删除。

### 第三步：重写并保留证据账本

心里将信息区分为四类：原书或原稿明确表达的观点、可核验事实、编辑推断、行动建议。后两类不得伪装成前两类。健康、教育、心理、财务或其他高风险建议必须保留限制条件，必要时建议读者寻找专业支持。

### 第四步：做格式、图片与朗读验收

格式和配图只为理解服务。图片要解释段落中的具体概念；表格用于横向对照；提示容器只承载真正需要强调的边界或行动。完成后按文末清单自检。

## 推荐叙事结构

```text
标题：书名 + 一句最独特的核心结论
开场破题：金句 + 反常识观点或极端困境 + 本书承诺（30 秒内）
关键问题：3～5 个，先给结论再解释
核心框架：按主题展开“场景/问题 → 观点 → 推演 → 边界”
行动结尾：以自然的动作型标题给出一个最小、具体的行动，或留下一个可延伸的问题
```

不强制所有文稿使用全部层级；以书的内容和原稿质量为准。概念型书籍可突出框架，故事型书籍应保留推动结论的关键故事。

### 开头破题：30 秒抓住注意力

开头不从“欢迎收听”、作者履历、解读背景或全书目录开始。用约 80～150 字完成三件事：

1. **金句前置**：第一句说清这本书解决的根本问题
2. **冲突切入**：抛出一个反常识观点，或一个读者熟悉的极端困境
3. **阅读承诺**：说明下文会解释什么新的视角、判断或方法

模板：

> **这本书解决的根本问题是：___。** 如果 ___，为什么反而会 ___？作者给出的反常识答案是 ___。接下来，我们就看这套判断如何成立。

开头只负责让读者进入问题，详细论证留给正文。避免在 30 秒内塞入过多结论或背景信息。

## 编辑决策：删什么，留什么，怎样改

### 直接删除

- 平台欢迎语、主播与解读人介绍、作者无关履历
- 音频、文稿、分享、购买或阅读原书等导流话术
- 与本书论点无关的个人经历
- 同一观点的重复反问、感叹和多轮举例

### 必须保留或压缩保留

- 核心论点及其因果链
- 有助理解作者立场的一个典型场景
- 章节间必要转场和段末小结
- 争议性观点的来源、适用范围或不能推导出的结论

### 保留案例，但压缩案例

案例不是装饰，而是让抽象观点可被代入的证据。每条核心主线优先保留一个短案例；案例较多时，保留最能展示“说法或行动改变后，关系/结果如何变化”的一个。

推荐结构：

```text
案例标题：一句话说明场景中的转变
孩子/当事人：发生了什么
容易出现的回应：原本会怎么说、怎么做
更有帮助的回应：改成什么说法、什么动作
一句解释：为什么这一改变有效，边界在哪里
```

案例应压缩为一个小场景，不逐句转录长对话；保留推动结论的关键两到四句即可。可使用引用块或“反例 / 改说法”表格呈现，避免多个同质案例连续堆叠。

### 处理“车轱辘话”

同一信息只保留一次完整表达。后续重复内容优先：

1. 删除没有新增信息的句子
2. 将不同表述合并成一条更短的因果链
3. 需要承接时，用逻辑连接词推进，不另起一轮解释

优先使用“换句话说”“本质上”“这意味着”“因此”“但边界是”串联逻辑；少用连续反问、感叹和“你有没有发现”式引导。

示例：

> 原意：父母持续进步，孩子会跟着进步；你做到了，比说一万句都有用。
>
> 改写：父母持续成长，比反复说教更有示范力。换句话说，孩子模仿的不是要求，而是每天看见的生活方式。

## 事实、观点与表达边界

- 作者观点使用“书中认为”“作者主张”“这一视角指出”，不要无依据地改写为普遍事实
- 避免“必然”“唯一”“注定”等绝对化结论；证据不足时改为“可能”“通常”“值得警惕”
- 健康、心理、教育建议应说明个体差异；不把单一训练、饮食或教养方式写成通用处方
- 保留自然口语，但一段只服务于一个观点，避免口语填充词堆叠

## Markdown 与图片表达

格式必须服务信息，不为装饰堆叠语法。优先按信息关系选择：

| 信息类型 | 推荐格式 |
| --- | --- |
| 全文最重要的视角 | `::: tip` 摘要容器 |
| 多个并列概念或对照关系 | Markdown 表格 |
| 一句话原则、关键转折 | 引用块 `>` |
| 必须限定的适用范围 | `::: info`；存在风险时用 `::: warning` |
| 可执行的收尾动作 | `::: tip` 行动卡片 |
| 有先后顺序的流程 | 有序列表 |

使用规则：

- 标题层级从 `#` 开始顺序递进，不跳级
- 使用 **粗体** 标示一句中的关键结论，不整段加粗
- 表格只用于横向对照；单列信息使用列表或段落
- 不使用 `::: details` 折叠内容；听书稿的补充说明应直接展开
- `::: info` 用于补充解释与适用边界，`::: warning` 用于风险提醒，`::: tip` 用于核心结论或行动建议
- 提示容器仅用于真正需要强调或提醒的内容，每个章节不宜堆叠多个
- 代码格式仅用于术语、命令、变量或需要保持字面形式的外文词；不要把普通中文概念写成代码

### 图片提取与图床命名

从 Word、PDF 等源文件提取图片时，先将图片存放在文章所在目录或其专用图片子目录，再写入 Markdown。提取文件不得使用容易与其他文章冲突的 `image1.jpeg`、`image2.png` 等通用名称。

- 文件名使用“文章短标识 + 时间戳或唯一值 + 序号”的形式，例如 `hongchun-meijiu-20260906-01.jpeg` 或 `hongchun-meijiu-a8f31c-01.jpeg`
- 同一篇文章的图片使用同一批次标识，序号按正文出现顺序递增，便于核对图片与批注
- 上传 PicGo 等图床前保持该唯一文件名，避免不同文章上传后互相覆盖
- Markdown 使用图床链接时，保留 `alt` 和居中图注；上传完成后抽查链接可访问性
- 未经明确要求，不删除文章目录中已压缩的本地图片，保留其作为可替换图床的源文件

### 外部图库配图、压缩与 PicGo 上传流程

需要补充外部图片时，先让图片服务于文章中的一个具体概念，再选图；不要为了丰富版面连续堆叠同类酒瓶、食物或风景图。同一概念通常保留 1～2 张最典型的图片即可。

### 选图的语义与构图验收

- **让主体服务段落。** 讲工艺设备时，优先选择设备本体、工序动作或原料关系清楚的画面；人物可以作为尺度或操作提示，但不应遮挡设备、占据画面重心或把图片变成人物肖像。
- **先看缩略图再下载。** 下载前核对主体是否一眼可辨、构图是否适合正文宽度、背景是否存在干扰元素，以及图片能否直接回答所在段落的问题。主体不突出、焦点落在无关人物、品牌标识过强、器物结构或光影明显失真、疑似生成式合成图，或画面信息与正文不匹配时，直接换图。
- **上传后做最终视觉检查。** 除文件大小、清晰度和水印外，还要在文章实际图片比例下复核。若读者第一眼无法看出该图为何放在此段，或图注需要过度解释才能成立，就应更换，不把“已经上传”当作保留理由。
- **图库来源不等于真实摄影。** 即便页面标注为图库照片，也必须人工查看设备比例、重复纹理、管路连接、光影方向、透视关系和画面文字；任一关键细节明显失真时，视为疑似合成图并弃用，不因下载、压缩或上传已完成而降低标准。

1. **先核验来源与许可。** 优先使用明确标注可用许可的专业图库、机构官网或 Wikimedia Commons；避开电商详情图、品牌宣传图、截图和带水印素材。记录页面链接、作者或机构、许可说明，供图注和后续复核使用。
2. **逐站点、低频下载。** 不对同一站点并发抓取；每张下载之间间隔至少 10 秒。遇到 `429`、验证码或反爬页面时立即停止该站点的直接下载，改用该站的官方下载入口、公开 API 或另一个已核验的来源，不绕过访问限制。
3. **先落本地再压缩。** 将原图保存到文章专用 `images/` 目录，以“文章短标识 + 日期 + 序号”命名，例如 `beer-wheat-20260906-01.jpg`。将最长边压缩至文章实际需要的尺寸（通常不超过 1600 px），导出质量约 80～85 的 JPEG 或合适的 WebP；逐张查看，确认没有水印、明显压缩伪影、错误主体或文字。
4. **使用 PicGo 上传压缩后的成品。** 只上传已经验收的本地成品，保持文件名不变。命令行 PicGo 可使用已配置的配置文件执行：`picgo -c <config-path> upload <image-path>`。配置文件可能包含令牌，不能写入仓库、终端输出、文档或提交记录。
5. **上传后验证并归档。** 对返回的图床 URL 发起一次 `HEAD` 或小流量 `GET`，确认返回 `200` 和正确的图片 MIME 类型；随后写入 Markdown 的 `figure`、`img`、`alt` 和图注。图注应给出图片说明与来源/作者，许可有署名要求时按原许可完整署名。默认保留压缩后的本地成品作为图床替换源；若用户明确要求不保留本地副本，必须在图床验收和文内链接验证完成后再删除。不要把临时下载失败文件、重复候选图或含水印素材纳入文章目录。

已验证的最小验收项：本地图片可打开、尺寸与文件体积适合页面、图床 URL 可访问、图片语义与所在段落一致、`alt` 和来源图注齐全。

## 输出格式

交付时先给出结果摘要：文章主线、做出的关键结构调整、保留的边界，以及验证结果。除非用户要求逐段审阅，不罗列所有微小措辞变动。文章本身应自然呈现为完整文稿，而不是把“分析过程”写进正文。

## 何时停止

当文章已经有清楚主线、每个核心章节都有“观点 → 原因 → 结果”、事实与观点边界明确、结尾给出一个可执行动作或有效钩子时，停止继续润色。不要为了显得深入而反复改写同一个判断；也不要为了凑篇幅添加无法支撑主线的案例、金句或配图。

## 反模式

- **名词和金句展览**：堆叠概念、书摘或修辞，却没有解释它们如何影响读者的判断。
- **只删不重组**：删掉重复后不补论证链，最终留下空心提纲。
- **伪造确定性**：把作者观点、个案经验或编辑推断写成普遍事实。
- **配图凑版面**：同类酒瓶、食物或风景连续出现，却不能解释段落。
- **把流程当目的**：图片已上传、格式已调整，不等于内容已经更易理解。

## 结尾：行动，而非全书复述

结尾不再总结全书框架，也不使用“以上就是本书解读”等收束语。根据文稿选择其一：

行动建议与思考钩子通常二选一，避免结尾同时承担两个重点。

### 给出一个最小行动

给出一个与全书核心方法一致、低门槛且可在本周开始的动作。动作必须具体，避免“多陪伴”“持续成长”这类空泛要求。

示例：

> 如果只做一件事，就在本周选一次亲子冲突，先不急着纠正孩子，先问自己：我希望他从这件事里学会承担什么后果？

### 留下一个钩子

提出一个没有被本书完全解决、但能引向更深问题的提问。钩子应来自本书的主线，不能是泛泛的鸡汤式设问。

示例：

> 当父母和孩子对“什么样的人生更好”有不同答案时，家庭规则究竟该保护谁的选择？

## 自检清单

- 开头能否在 30 秒内说明“这本书讲什么、为何值得听”
- 每个核心章节是否包含观点、理由和必要边界
- 是否删掉平台信息、人物介绍、导流和无关自述
- 是否删掉车轱辘话，而非删掉支撑主论点的推演
- 每条核心主线是否保留了一个能说明转变的短案例
- 连接词是否真正推进逻辑，而非把重复内容换一种说法
- 结尾是否只留下一个行动或一个钩子，而不是总结全书
- [ ] 是否能用一句话说清全文核心问题，而不是只列主题？
- [ ] 每个核心章节是否有明确工位，且存在“观点 → 原因 → 结果”的完整链条？
- [ ] 是否区分了作者观点、可核验事实、编辑推断与行动建议？
- [ ] 是否删掉了不能改变理解或行动的重复内容，而没有删掉论证？
- [ ] 图片、表格和提示容器是否都能直接服务所在段落？
- [ ] 是否存在一句会因新事实或不同前提而需要改写的绝对化表达？
