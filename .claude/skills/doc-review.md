# 文档审查技能

逐项检查 Markdown 文档中的问题，按优先级排列。代码块内部不检查格式问题（空格、标点），但需要检查代码正确性。

## 1. 缩进无前缀（语雀兼容性）

缩进段落缺少列表标记 `-`/`1.`，语雀不会渲染为列表项。这是最常见的问题。

```markdown
# 错误 — 语雀无法识别
- 父级列表项

  缩进的独立段落

  另一个缩进段落

# 正确
- 父级列表项

  - 缩进的子项

  - 另一个缩进子项
```

**判断标准：** 缩进文本是独立的观点/条目（而非对上一行的解释说明），必须加 `-`。

## 2. 语病 / 语法错误

句子成分残缺、搭配不当、重复冗余。

| 类型 | 示例 |
|---|---|
| 成分残缺 | "编写就可" → "编写就可以" |
| 成分残缺 | "遇到需要组件之间相互通信" → "遇到…的情况" |
| 成分残缺 | "内容是不固定" → "内容是不固定的" |
| 搭配不当 | "称之为是" → "称之为" |
| 搭配不当 | "最直接的方式找到" → "以最直接的方式找到" |
| 重复冗余 | "好用的好用特性" → "好用的特性" |
| 重复冗余 | "是就是" → "就是" |
| 语序不当 | "我们传入给其他地方的响应式对象希望被使用但不能修改" → "我们希望传递给其他组件使用的响应式对象不被修改" |
| 错用字 | "用于可能会" → "我们可能会" |

## 3. 语义错误 / 歧义

表达含义与实际意图相反或模糊不清。

| 原文 | 问题 | 修正 |
|---|---|---|
| 希望插槽中没有显示每项的内容 | 与作用域插槽本意相反 | 希望插槽能够自定义每项内容的显示方式 |
| 其对应的原生不会被渲染 | "原生"含义不明 | 其对应的**元素** |
| 可以自定来定义 | 语素颠倒 | 可以**自行**来定义 |
| 六个步骤：扫描→生成→注入 | 只有3阶段却说6步骤 | 三个阶段，细分为六个步骤 |
| 模板引擎可以简化视图操作，没办法跟踪状态 | 缺少转折 | 模板引擎可以简化视图操作，**但**没办法跟踪状态 |

| 问题 | 修正 |

## 12. 代码示例错误

代码块内容存在语法错误或结构问题，导致复制后无法正常运行。此类问题在文档中容易被忽略，但对读者体验影响极大。

| 问题 | 示例 | 修正 |
|---|---|---|
| 括号不匹配 | `createStore({...}` — 缺少 `)` | `createStore({...})` |
| 缺少函数/方法包装 | `export default { const state = ... }` — 缺少 `setup()` | `export default { setup() { ... } }` |
| API 名称写错 | `navigatorTo`、`commit('mutation', payload)` | `navigateTo`、`commit('mutation', payload)` 确认 API 存在 |
| 代码块缺少闭合标签 | `<script>` 无 `</script>` | 补全闭合标签 |
| 静态属性误用 `:` 绑定 | `<el-dialog :title="弹出框">` — 文本不需要 `:` | `<el-dialog title="弹出框">` |
| 运算符优先级 | `if (!key in obj)` — `!` 优先级高于 `in` | `if (!(key in obj))` |
| 正则表达式缺陷 | `class=["']([^"']+)["']` 漏匹配 `className` | 改为 `class(?:Name)?=["']([^"']+)["']` |
| 废弃 API | `contentBase` 是 webpack-dev-server v3 配置 | 改为 `static: { directory: '...' }` |
| 变量/组件名重复声明 | `const User =` 在同一作用域声明两次 | 改为不同变量名 `User2` |
| 示例缺少导出或导入 | 路由数组未 `export default` | 补齐可运行的最小依赖、导出和调用位置 |
| 旧构建插件仍作为默认方案 | `file-loader`、`url-loader`、`eslint-loader` | 标注适用的旧版本；新 Webpack 使用 Asset Modules、ESLint CLI 或对应插件 |
| 不安全的运维示例 | 以 root 运行服务、直接删除线上目录 | 改为最小权限、构建校验、版本化产物与可回滚发布 |
| 下载二进制、运行远程脚本或设置可执行权限 | 固定可信来源与校验和，避免 `curl | sh`；使用最小权限如 `755`，不得使用 `777` |
| Worker 示例错误地将对象描述为 JSON 字符串传递，或把 `importScripts()` 用于模块 Worker | 使用结构化克隆与 transfer list 的准确语义；区分经典 Worker 的 `importScripts()` 和模块 Worker 的 `import` |
| Proxy trap 未返回布尔结果，或示例在同一作用域重复声明 | 遵循 Proxy invariants；保留唯一声明并使示例可独立执行 |
| 泛型或 `keyof` 示例未真正参与约束，或对象遍历仍以任意字符串索引泛型 | 让泛型贯穿入参与返回值；使用 `Object.keys()` 与 `Array<keyof T>` 等受控断言 |
| 函数式示例重复声明、错误递归调用，或缓存/异步分支未保持语义 | 保持唯一标识符；递归返回正确的闭包；缓存用存在性判断并保留调用方 `this`，失败分支及时返回 |
| 将小程序 WXML、WXSS 与页面 JS 混在同一代码块 | 按实际文件边界拆分代码块，并分别使用 `html`/`css`/`js` 语言标注，保证语法高亮和复制可用 |
| `parseInt` 直接作为 `map` 回调，或 `Promise.all` 忽略空输入 | 显式传入基数或使用单参包装；空输入应立即解析为 `[]` |

> **重要：区分有意为之和无意错误。** 教学文档中，"未注册的组件""未导入的函数""冗余的全局注册"等，往往是作者故意展示的场景（如演示打包体积浪费、对比正确与错误写法）。判断标准：看上下文是否有明确的解释说明——如果文字解释了"为什么这样不好"，则代码是故意示范，不应标记为错误。

## 13. 知识补充原则

当文章缺少理解关键概念所必需的信息时，补充最小可用说明，不扩写成教程。

- 优先说明职责、数据流、边界条件和常见误区。
- 先给整体关系，再说明局部 API 或实现细节。
- 补充内容应能回答“谁负责、何时发生、数据如何流动”，并保持简短。

### 本批新增规则

- 小程序授权 API 需区分历史接口与当前用户授权流程；敏感身份数据应由服务端换取或校验，不能在客户端保存密钥。
- 浏览器渲染和空闲调度属于宿主实现，不能把具体时序、帧预算或等待毫秒数写成跨版本保证；应以目标设备实测为准。
- 性能指标需标注实验室指标与真实用户指标的用途，避免继续把已退出核心指标的 TTI 当作唯一结论。
- 构建优化文章中的旧插件和旧框架 API 必须标注版本边界，并给出现代链路的替代方向。
- 升级 VitePress、Shiki 或 Sass 后必须执行完整生产构建；原生依赖需确认构建脚本已执行，并记录仅警告项（如 Sass `@import` 弃用）而非将警告误判为失败。
- 项目 README 应与 `package.json` 脚本、目录结构和部署 `BASE` 保持一致；新增目录需同步说明用途和命名约定。

## 审查顺序

1. 先扫 **缩进无前缀**（最高频，语雀渲染直接影响最大）
2. 逐段通读，关注句子通顺和歧义
3. 检查中英文空格、标点
4. 检查错别字、术语一致性
5. 检查概念/术语使用是否准确（技术翻译错误）
6. 检查内容完整性、结构与注释准确性（残留碎片、重复块、章节位置、变量重名、一级标题是否唯一、注释与当前配置、脚手架与版本命令是否仍有效、历史环境是否被误作推荐）
7. 检查代码示例是否正确与安全（括号匹配、结构完整、导入导出、API 有效性、运算符优先级、正则正确性、废弃 API、最小权限与可回滚）
8. 检查代码块语言标注（`js`/`ts`/`html` 是否匹配内容）
9. 代码块内部不检查格式问题（空格、标点）
10. 列表项紧跟的代码块/图片属于正常格式，不检查
11. 发现知识点缺少职责、数据流或边界说明时，补充最小必要的架构说明

12. React/Fiber 教学实现必须标注与当前 React 的边界；检查父级查找、遍历推进、更新/删除分支是否会造成死循环或把组件 fiber 当作 DOM 节点，并说明 key、卸载清理等未覆盖能力。
