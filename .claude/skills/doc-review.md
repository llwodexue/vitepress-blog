# 文档审查技能

逐项检查 Markdown 文档中的问题，按优先级排列。代码块内部不检查格式问题（空格、标点），但需要检查代码正确性。

---

## 1. 缩进无前缀（语雀兼容性）

缩进段落缺少列表标记 `-`/`1.`，语雀不会渲染为列表项。这是最常见的问题。

```markdown
# 错误 — 语雀无法识别
- 父级列表项

  缩进的独立段落

  另一个缩进段落

# 正确
- 父级列表项

  - 缩进的子项

  - 另一个缩进子项
```

**判断标准：** 缩进文本是独立的观点/条目（而非对上一行的解释说明），必须加 `-`。

## 2. 语病 / 语法错误

句子成分残缺、搭配不当、重复冗余。

| 类型 | 示例 |
|---|---|
| 成分残缺 | "编写就可" → "编写就可以" |
| 成分残缺 | "遇到需要组件之间相互通信" → "遇到…的情况" |
| 成分残缺 | "内容是不固定" → "内容是不固定的" |
| 搭配不当 | "称之为是" → "称之为" |
| 搭配不当 | "最直接的方式找到" → "以最直接的方式找到" |
| 重复冗余 | "好用的好用特性" → "好用的特性" |
| 重复冗余 | "是就是" → "就是" |
| 语序不当 | "我们传入给其他地方的响应式对象希望被使用但不能修改" → "我们希望传递给其他组件使用的响应式对象不被修改" |
| 错用字 | "用于可能会" → "我们可能会" |

## 3. 语义错误 / 歧义

表达含义与实际意图相反或模糊不清。

| 原文 | 问题 | 修正 |
|---|---|---|
| 希望插槽中没有显示每项的内容 | 与作用域插槽本意相反 | 希望插槽能够自定义每项内容的显示方式 |
| 其对应的原生不会被渲染 | "原生"含义不明 | 其对应的**元素** |
| 可以自定来定义 | 语素颠倒 | 可以**自行**来定义 |
| 六个步骤：扫描→生成→注入 | 只有3阶段却说6步骤 | 三个阶段，细分为六个步骤 |
| 模板引擎可以简化视图操作，没办法跟踪状态 | 缺少转折 | 模板引擎可以简化视图操作，**但**没办法跟踪状态 |

## 6. 标点符号

中文环境用中文标点，不混用。

| 错误 | 正确 |
|---|---|
| 英文逗号分隔中文：`A, B` | `A，B` |
| 英文分号分隔中文：`A; B` | `A；B` |
| 英文冒号：`A: B` | `A：B` |
| 英文括号：`url_hash(需安装)` | `url_hash（需安装）` |
| 多余分号结尾：`来监听；` | `来监听` |
| 多余"的"：`在部署的时` | `在部署时` |
| 缺少分隔符：`（使用v-if）条件展示` | `（使用 v-if）、条件展示` |

## 10. 概念 / 术语使用错误

技术术语的翻译或使用存在概念性错误，而非简单拼写问题。

| 原文 | 问题 | 修正 |
|---|---|---|
| Docker 守护线程 | daemon 是守护**进程**，不是线程 | Docker 守护**进程** |
| 全站 HTTPS，即 HTTP 加密 | HTTPS 是 HTTP over SSL/TLS | 全站 HTTPS，即 **HTTP over SSL/TLS** |
| 浏览器解释 JavaScript | 浏览器是执行/运行 JS，不是解释 | 浏览器**执行** JavaScript |
| 增量为 1 3 5 7 | 2^k-1 的序列是 1、3、7、15 | 增量为 1、3、7、15... |
| 高阶组件返回的高阶组件 | connect 是高阶**函数**，返回高阶组件 | 高阶**函数**返回的高阶组件 |
| navigatorTo | 小程序 API 是 navigateTo | navigateTo |

## 12. 代码示例错误

代码块内容存在语法错误或结构问题，导致复制后无法正常运行。此类问题在文档中容易被忽略，但对读者体验影响极大。

| 问题 | 示例 | 修正 |
|---|---|---|
| 括号不匹配 | `createStore({...}` — 缺少 `)` | `createStore({...})` |
| 缺少函数/方法包装 | `export default { const state = ... }` — 缺少 `setup()` | `export default { setup() { ... } }` |
| API 名称写错 | `navigatorTo`、`commit('mutation', payload)` | `navigateTo`、`commit('mutation', payload)` 确认 API 存在 |
| 代码块缺少闭合标签 | `<script>` 无 `</script>` | 补全闭合标签 |

> **重要：区分有意为之和无意错误。** 教学文档中，"未注册的组件""未导入的函数""冗余的全局注册"等，往往是作者故意展示的场景（如演示打包体积浪费、对比正确与错误写法）。判断标准：看上下文是否有明确的解释说明——如果文字解释了"为什么这样不好"，则代码是故意示范，不应标记为错误。

## 审查顺序

1. 先扫 **缩进无前缀**（最高频，语雀渲染直接影响最大）
2. 逐段通读，关注句子通顺和歧义
3. 检查中英文空格、标点
4. 检查错别字、术语一致性
5. 检查概念/术语使用是否准确（技术翻译错误）
6. 检查内容完整性（残留碎片、重复块）
7. 检查代码示例是否正确（括号匹配、结构完整）
8. 检查代码块语言标注
9. 代码块内部不检查格式问题
10. 列表项紧跟的代码块/图片属于正常格式，不检查
